## 3. 当前问题、本次目标与假设

已核对的开发结果显示任务一、二加入表面分支后有增益，任务三尚未显示稳定增益。这些实验各自训练 adapter 与任务头，尚不构成冻结 adapter 的跨任务迁移证据。

关键缺口是：当前 dMaSIF 权重的确切监督训练成员未知。历史审计记录仓库 `training_ppi.txt` 与发布 DIPS train/validation/test 的 PDB 交集为 2,810/230/129 个，对应 10,902/1,667/980 条发布记录。这些是历史全发布划分的列表交集；不能当作当前选中子集的交集，也不能当作目标 checkpoint 的已证实训练成员。

本次只回答两个问题：

1. 能否将目标权重的确切字节身份，与可信的下载来源、发布版本、原训练配置和训练成员建立可追溯关联？
2. 已有重叠审计究竟覆盖哪个权重、哪份列表、哪个数据范围和什么重叠层级；是否已有针对当前 4,861/467 复合物的结果？

待检验的假设是：现有证据足以界定监督重叠风险，并据此判断是否具备进一步设计独立评测的条件。允许结果为不支持或未知。

| 可能发现 | 对研究决策的影响 |
| --- | --- |
| 权重与训练成员关联可靠，已有审计能界定所覆盖的重叠范围 | 可讨论补足独立评测协议；这本身不等于已证明所有层级无泄漏 |
| 有可靠训练成员关联，且已有结果显示同一评测蛋白、界面或同源成员重叠 | 明确受影响层级，保留当前开发结果，另行讨论排除重叠的评测设计 |
| 只有仓库列表与 PDB 交集，缺少列表到权重的关联 | 维持“存在风险线索、实际监督重叠未确定”，不得升级为已证实泄漏或无泄漏 |
| 来源或成员在限定范围内无法确认 | 以未知完成，说明缺失环节；后续是否继续开发诊断或更换方案由用户决定 |
