## 三、Slurm 作业系统使用规范

### 3.1 核心原则

**❌ 禁止在登录节点运行计算任务**
- 所有 Python 训练/推理必须通过 `sbatch` 提交到计算节点
- 登录节点只用于：文件管理、编辑脚本、提交作业、查看队列

**✅ 正确的工作流程：**
```bash
# 1. 在登录节点编写作业脚本
vim my_job.sbatch

# 2. 提交到计算节点
sbatch my_job.sbatch

# 3. 查看作业状态
squeue -u zhangye

# 4. 查看输出日志
tail -f slurm-<JOBID>.out
```

### 3.2 作业脚本模板

#### GPU 作业示例
```bash
#!/bin/bash
#SBATCH --job-name=my_task          # 作业名称
#SBATCH --partition=a40             # 分区：a40 / a100
#SBATCH --nodes=1                   # 节点数
#SBATCH --ntasks-per-node=1         # 每节点任务数
#SBATCH --cpus-per-task=8           # CPU 核心数
#SBATCH --gres=gpu:1                # GPU 数量
#SBATCH --output=logs/%x_%j.out     # 标准输出
#SBATCH --error=logs/%x_%j.err      # 错误输出

# 激活环境
source /datapool/home/zhangye/protein-models/miniconda3/etc/profile.d/conda.sh
conda activate my_env

# 进入项目目录
cd /datapool/home/zhangye/projects/MyProject

# 运行任务
python train.py --config configs/default.yaml
```

#### CPU 作业示例
```bash
#!/bin/bash
#SBATCH --job-name=cpu_task
#SBATCH --partition=cpu             # CPU 分区
#SBATCH --nodes=1
#SBATCH --cpus-per-task=16
#SBATCH --output=logs/%x_%j.out

source /datapool/home/zhangye/protein-models/miniconda3/etc/profile.d/conda.sh
conda activate my_env

cd /datapool/home/zhangye/projects/MyProject
python inference.py --device cpu
```

### 3.3 常用 Slurm 命令

```bash
# 提交作业
sbatch job.sbatch

# 查看队列
squeue -u zhangye

# 取消作业
scancel <JOBID>

# 取消所有作业
scancel -u zhangye

# 查看作业详情
scontrol show job <JOBID>

# 查看分区信息
sinfo

# 查看节点状态
scontrol show node <NODE_NAME>
```

### 4.4 已知环境问题与解决方案

#### 问题 1：`GLIBCXX_3.4.30` 缺失
```bash
# 症状
ImportError: /lib64/libstdc++.so.6: version `GLIBCXX_3.4.30' not found

# 解决
conda install -c conda-forge libstdcxx-ng=12.2
```

#### 问题 2：CUDA 版本不匹配
```bash
# 检查系统 CUDA
nvidia-smi  # 查看驱动支持的 CUDA 版本

# 安装匹配的 PyTorch
# 如果驱动是 CUDA 11.7
pip install torch==2.0.1+cu117 -f https://download.pytorch.org/whl/torch_stable.html
```

#### 问题 3：conda 环境损坏
```bash
# 症状：python 可执行文件消失、pip 报错

# 解决：删除重建
conda remove -n broken_env --all
conda create -n my_env python=3.11
```

## 五、数据与权重管理

### 5.1 大文件下载规范

**❌ 禁止占用登录节点长时间下载**

**✅ 正确做法：**

#### 方案 A：使用后台作业
```bash
# 1. 写下载脚本 download.sbatch
#!/bin/bash
#SBATCH --job-name=download
#SBATCH --partition=cpu
#SBATCH --cpus-per-task=4
#SBATCH --output=download_%j.log

cd /datapool/home/zhangye/projects/MyProject
wget https://example.com/large_file.tar.gz
```

#### 方案 B：使用 nohup（小文件可接受）
```bash
nohup wget https://example.com/file.tar.gz > download.log 2>&1 &
```

### 5.2 Git LFS 文件处理

**集群未安装 `git-lfs`，需要手动下载：**

```bash
# 1. 查看 LFS 指针文件
cat ckpts/model.pt
# version https://git-lfs.github.com/spec/v1
# oid sha256:abc123...
# size 297051243

# 2. 构造下载 URL
# GitHub: https://media.githubusercontent.com/media/<user>/<repo>/main/<path>

# 3. 使用分块下载器（见 VITAL 项目中的 vital_ckpt_v2.py）
python vital_ckpt_v2.py
```

### 5.3 数据完整性校验

**下载后必须校验：**

```bash
# MD5 校验
md5sum large_file.tar.gz

# SHA256 校验
sha256sum model.pt

# 与官方提供的哈希值对比
```

## 六、常见陷阱与调试技巧

### 6.1 计算节点无外网

**症状：** 作业运行时报 `Connection refused` / `Unable to download`

**原因：** 计算节点没有外网连接

**解决：**
- 所有外部依赖必须在登录节点预先下载
- 权重文件、数据集、预训练模型都提前准备好
- 使用离线安装包：`pip download` + `pip install --no-index`

```bash
# 登录节点下载
pip download torch==2.0.1 -d /tmp/torch_wheels/

# 作业脚本中安装
pip install --no-index --find-links=/tmp/torch_wheels/ torch
```

### 6.2 进程管理陷阱

**危险操作：**
```bash
# ❌ 在 ssh 会话中用 pkill 结束自己提交的进程
pkill -f my_script.py  # 可能杀死 ssh 自身！
```

**正确做法：**
```bash
# ✅ 通过 Slurm 管理
scancel <JOBID>

# ✅ 如果必须用 kill，先找准 PID
ps -ef | grep my_script
kill <PID>  # 只杀特定进程
```

### 6.3 日志文件管理

**问题：** 日志文件膨胀占满磁盘

**规范：**
```bash
# 1. 日志统一放在 logs/ 目录
mkdir -p /datapool/home/zhangye/projects/MyProject/logs

# 2. 定期清理旧日志
find logs/ -name "*.out" -mtime +30 -delete  # 删除 30 天前的日志

# 3. 使用日志轮转
#SBATCH --output=logs/%x_%j.out  # %j 是 JOBID，自动避免覆盖
```

### 6.4 权限问题

**症状：** `Permission denied` / `Read-only file system`

**检查：**
```bash
# 查看文件权限
ls -lh /path/to/file

# 修复权限
chmod 644 file.txt
chmod 755 script.sh

# 检查磁盘配额
quota -s
```

## 八、VITAL 项目实例

这是一个完整的实战案例，展示了如何应用上述规范：

**项目位置：** `/datapool/home/zhangye/projects/VITAL/`

**核心发现：**
- ✅ 推理代码完整，权重文件可用
- ❌ 训练代码缺失，全量数据未提供
- ✅ 10/10 样例推理结果与作者参考一致（bit-level）

**踩过的坑：**
1. 权重是 Git LFS 指针，集群无 `git-lfs` → 手写分块下载器 + sha256 校验
2. GitHub 直连慢（45KB/s）→ 使用 `gh-proxy.com` 镜像
3. conda 环境创建中途 DNS 故障 → 删除重建
4. 下载器 v1 有"假成功"bug（重试耗尽后静默跳过坏块）→ 重写成逐块持久化 + 全 0 扫描

**可复用产物：**
- `vital_pred_cpu.sbatch`：CPU 推理作业模板
- `vital_ckpt_v2.py`：带校验的大文件下载器
- `README.md`：完整的项目文档
